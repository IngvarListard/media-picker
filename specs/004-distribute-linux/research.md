# Research: установка и запуск на любом Linux

## Решения

| Решение | Обоснование | Рассмотренная альтернатива |
|---|---|---|
| Ставить приложение как обычный пакет из публичного каталога: одна команда установки, запуск по короткому имени `media-picker`. | Графическая библиотека приходит внутри пакета, поэтому система без Qt (например GNOME) не мешает. Пользователю не нужны исходники, а обновление — повтор той же команды. | Готовый образ приложения без установки и Flatpak-сборка: больше работы, песочница конфликтует с «mpv ставит пользователь». Отдельный этап. |
| Зависимость `pyside6-essentials` вместо полного `pyside6`. | Проверено: код импортирует только `QtCore` и `QtWidgets`, а Essentials содержит QtCore/QtGui/QtWidgets/QtSvg и другие базовые модули, но не Addons (WebEngine, 3D, Charts). Пакет и установка заметно легче. | Полный `pyside6`: в локальном окружении это 648 МБ, из которых приложению нужна малая часть. |
| Не переносить модули в каталог-пакет: объявить `media_picker` и `files` как `py-modules`. | Минимальная правка: файлы остаются на месте, импорты, тесты и команда `uv run python media_picker.py` не меняются. Сборочная система — setuptools, она поддерживает плоские модули явно. | Каталог-пакет `media_picker/` с переносом `files.py` внутрь: чище для пакетных данных, но правка импортов и тестов без выгоды на этом этапе. |
| Минимальные системы определяются версией системной библиотеки, которую требует поставляемая графическая библиотека: Ubuntu 22.04+, Debian 12+, Fedora 35+. | Проверено по `uv.lock`: колесо для x86_64 помечено `manylinux_2_34`, то есть нужен glibc ≥ 2.34. Обещать работу на более старых системах нельзя. | Собрать ветку на старом выпуске графической библиотеки ради Debian 11 и RHEL 8: отдельная сборочная ветка и поддержка двух версий без запроса. Отложено. |
| Путь к mpv ищется так: явный путь из настроек, затем `PATH`. | Пользователь может поставить mpv в любое место, а обычный случай (пакет дистрибутива) работает без настройки. Поиск — чистая функция, легко проверяется. | Своя установка mpv внутрь приложения: противоречит выбранному «пользователь ставит mpv сам». Только переменная окружения: неудобно для ярлыка из меню. |
| При отсутствии mpv приложение работает дальше и объясняет установку, а не блокирует кнопку и не падает. | Навигация, выбор файлов и настройки полезны и без mpv; после установки mpv запуск происходит без перезапуска приложения. | Блокировать кнопку: пользователь не понимает, чего не хватает. Падать с исключением: неприемлемо для установленного приложения. |
| Папку загрузок брать у системы, а не собирать как `домашняя/Downloads`. | На локализованных системах папка называется иначе, а расположение может быть изменено пользователем. Qt уже используется в проекте, отдельная зависимость не нужна. | Читать переменные окружения вручную: дублирует Qt и не учитывает настройки системы. |
| Имя пакета — `media-picker`, команда запуска — та же. | Проверено: в публичном каталоге пакета с таким именем нет (запрос вернул 404), а имя совпадает с именем проекта и заголовком окна. | Другое имя: пришлось бы объяснять расхождение с названием приложения. |
| Запись в меню ставится отдельной документированной командой для текущего пользователя. | Установка пакета кладёт только команду запуска; меню — отдельное действие, не требующее прав root и не ломающееся при обновлении пакета. | Установка записи в меню прямо из установщика пакета: у окружений с изолированными каталогами записи всё равно не подхватываются автоматически. |
| Идентификатор приложения `io.github.IngvarListard.MediaPicker` для записи в меню, значка и метаинфо. | Совпадает с владельцем и именем репозитория; такой формат требуют публичные каталоги приложений, поэтому переименовывать позже не придётся. | Короткое имя `media-picker.desktop`: пришлось бы переименовывать при первой же публикации в каталог приложений. |
| Публикация пакета и сборка — в GitHub Actions по тегу, через доверенную публикацию. | Не нужны долгоживущие токены; проверки и сборка воспроизводимы. До первой публикации установка идёт напрямую из репозитория. | Ручная сборка и загрузка: легко забыть шаг и собрать из грязной копии. |

## Интеграционные замечания

- `launch()` уже проверяет существование выбранных файлов и вызывает процесс списком аргументов; меняется только источник пути к mpv и сборка этого списка — вынести её в чистую функцию, чтобы проверить порядок аргументов тестом.
- `QSettings` использует формат INI и область пользователя, поэтому новый ключ `options/mpv_path` появляется в том же файле, что и остальные настройки, без миграции.
- Проверка «нет mpv» не должна мешать существующему правилу: при проблемах с дорожками кнопка «Смотреть» недоступна, сообщение показывается в панели. Предупреждение об отсутствии mpv — отдельное, немодальное.
- Значок окна и запись в меню — разные вещи: запись отвечает за вид в меню и списке задач, значок окна нужен при запуске без записи (из терминала). Делаем оба.
- Desktop-запись без аргумента-пути (`%F`) не требует объявлять поддерживаемые типы файлов; открытие видео из файлового менеджера остаётся за рамками этапа.

### Проверенные источники и ограничения

- [Qt for Python: Package Details](https://doc.qt.io/qtforpython-6/package_details.html) подтверждает состав пакетов: `pyside6` в версии 6.3+ почти пуст и ссылается на `pyside6-essentials`, `pyside6-addons` и `shiboken6`; бинарники Qt лежат в Essentials и Addons. [PySide6-Essentials](https://pypi.org/project/PySide6-Essentials/) перечисляет модули Essentials, включая QtCore, QtGui и QtWidgets.
- Локально проверено: `.venv/lib/python3.12/site-packages/PySide6` занимает 648 МБ и содержит `libQt6Core.so.6`, `libQt6Gui.so.6`, `libQt6Widgets.so.6`; в проекте импортируются только `PySide6.QtCore` и `PySide6.QtWidgets`.
- Локально проверено по `uv.lock`: колёса `pyside6` 6.11.2 для Linux помечены `manylinux_2_34_x86_64` и `manylinux_2_39_aarch64`. Обсуждение на форуме Qt ([Why does PySide6 need glibc 2.39 since 6.8.1 on aarch64?](https://forum.qt.io/topic/161232/why-does-pyside6-need-glibc-2-39-since-6-8-1-on-aarch64)) подтверждает, что пол растёт вместе с используемым выпуском дистрибутива сборки: на x86_64 это 2.34, на aarch64 — 2.39.
- Проверено: `https://pypi.org/pypi/media-picker/json` отвечает 404 — имя свободно.
- [Qt: QStandardPaths](https://doc.qt.io/qt-6/qstandardpaths.html) описывает `DownloadLocation` как стандартное место загрузок; оно учитывает локаль и настройки пользователя, в отличие от жёсткого `~/Downloads`.
- Для сравнения рассмотрены и отложены: [python-appimage](https://python-appimage.readthedocs.io/en/latest/apps/) и [Briefcase/AppImage](https://briefcase.beeware.org/en/stable/reference/platforms/linux/appimage/) вместо пакета — требуют отдельного сборочного окружения на старом выпуске дистрибутива и известных доработок под PySide6 (xcb, падения), поэтому это отдельный этап, а не часть текущей спеки.
