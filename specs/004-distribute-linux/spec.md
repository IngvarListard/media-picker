# Feature Specification: Установка и запуск на любом Linux

**Feature Branch**: `004-distribute-linux`

**Created**: 2026-10-08

**Status**: Draft

**Input**: Пользователь хочет тиражировать приложение: чтобы оно ставилось одной командой на любом Linux-дистрибутиве и десктопе (в том числе GNOME, где не установлен Qt), запускалось по имени из любого каталога, появлялось в меню приложений, а внешний mpv пользователь ставил сам — но при его отсутствии получал понятную подсказку, а не ошибку.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Поставить и запустить на своём дистрибутиве (Priority: P1)

Пользователь работает на GNOME (Ubuntu, Fedora, Arch — не важно), исходников проекта у него нет, Qt в системе не установлен. Он открывает README, копирует одну команду установки, затем запускает приложение по имени и получает обычное окно с тремя панелями.

**Why this priority**: Сейчас приложение доступно только тому, кто умеет клонировать репозиторий, поставить окружение и запустить скрипт из папки проекта. Без этого шага тиража нет вообще.

**Independent Test**: На системе без установленного Qt выполнить документированную установку и запуск; окно открывается, папки листаются, выбор видео и дорожек работает как раньше.

**Acceptance Scenarios**:

1. **Given** в системе нет Qt и нет исходного кода проекта, **When** пользователь выполняет одну документированную команду установки, **Then** установка проходит без прав root и без ручной установки графических библиотек.
2. **Given** приложение установлено, **When** пользователь запускает его по короткому имени из произвольного каталога, **Then** окно открывается, а не возникает ошибка о ненайденном модуле.
3. **Given** приложение запущено на десктопе, отличном от KDE, **When** пользователь выбирает видео, внешние дорожки и нажимает «Смотреть», **Then** поведение не отличается от работы на KDE.
4. **Given** приложение установлено, **When** пользователь удаляет каталог с исходным кодом, **Then** приложение продолжает запускаться.
5. **Given** установлена предыдущая версия, **When** пользователь повторяет ту же команду установки, **Then** получает новую версию, не удаляя старую вручную.
6. **Given** приложение установлено, **When** пользователь переключает сессии Wayland и X11, **Then** окно открывается в обеих.
7. **Given** пользователь запускает приложение впервые, **When** окно открывается, **Then** показана папка загрузок текущего пользователя, даже если её имя на его языке отличается от «Downloads».
8. **Given** у пользователя старый дистрибутив или нет сети, **When** он читает инструкцию, **Then** инструкция заранее называет минимальные версии систем и требование однократного подключения к сети, а также приводит команды установки mpv для распространённых дистрибутивов.

### User Story 2 - Понять, чего не хватает для просмотра (Priority: P2)

mpv пользователь ставит сам. Если его нет, приложение не падает и не молчит, а объясняет, что нужно установить и какой именно командой — отдельно для распространённых дистрибутивов. Если mpv лежит в нестандартном месте, пользователь указывает путь в настройках.

**Why this priority**: mpv — единственная внешняя зависимость приложения. Без подсказки новый пользователь видит непонятное сообщение об ошибке и считает, что приложение сломано.

**Independent Test**: Сделать mpv невидимым для приложения (указать в настройках несуществующий путь) и проверить, что появляется понятное сообщение с командами установки, приложение остаётся работоспособным, а после появления mpv видео запускается без перезапуска.

**Acceptance Scenarios**:

1. **Given** mpv отсутствует в системе, **When** пользователь нажимает «Смотреть», **Then** показывается сообщение о необходимости установить mpv и команды для распространённых дистрибутивов; приложение не завершается.
2. **Given** mpv отсутствует, **When** пользователь открывает окно, **Then** предупреждение видно в панели видео, а навигация по папкам, выбор файлов и смена настроек продолжают работать.
3. **Given** mpv был установлен после запуска приложения, **When** пользователь снова нажимает «Смотреть», **Then** видео запускается без перезапуска приложения.
4. **Given** mpv установлен в нестандартном месте, **When** пользователь указывает путь к нему в настройках, **Then** запуск использует этот путь.
5. **Given** в настройках путь к mpv указан неверно, **When** пользователь нажимает «Смотреть», **Then** показывается то же понятное сообщение, а не ошибка запуска процесса.

### User Story 3 - Запускать из меню приложений (Priority: P3)

Пользователь не любит терминал и хочет запускать приложение из меню приложений, как любое другое: по значку и названию, без командной строки.

**Why this priority**: Приятно и ожидаемо для настольной программы, но не мешает установке и работе — можно добавить после того, как заработают первые два сценария.

**Independent Test**: Установить запись приложения в меню для текущего пользователя, найти приложение в меню по названию и запустить его мышкой.

**Acceptance Scenarios**:

1. **Given** приложение установлено, **When** пользователь выполняет документированную команду добавления в меню, **Then** приложение появляется в меню с названием и значком.
2. **Given** запись добавлена, **When** пользователь запускает приложение из меню, **Then** окно открывается без терминала.
3. **Given** значок и запись установлены, **When** окно открыто, **Then** в списке задач и в меню видно один и тот же значок, а не стандартная заглушка.

---

### Edge Cases

- **Локализованная папка загрузок**: при первом запуске на системе с русской локалью открывается папка «Загрузки», а не пустая домашняя.
- **Нет доступа к сети при установке**: установка не может завершиться — инструкция должна заранее называть требование к подключению.
- **Система старше поддерживаемой**: если графическая библиотека в составе приложения не запускается на старом дистрибутиве, инструкция должна называть минимальные версии систем, а приложение — не выдавать невнятную ошибку.
- **mpv есть, но не запускается** (например, нет прав на исполняемый файл): пользователь видит сообщение о неудачном запуске, выбор файлов сохраняется.
- **Несколько разных mpv в системе**: используется путь, указанный пользователем; при пустом значении — первый найденный в PATH.
- **Имя пакета занято в публичном каталоге**: на момент планирования свободно; если займут до публикации, установка из каталога под этим именем станет недоступна, но установка напрямую из репозитория проекта продолжит работать.
- **Пользователь работает без прав root**: установка и настройка выполняются полностью для текущего пользователя.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Приложение MUST устанавливаться одной документированной командой для текущего пользователя, без прав root.
- **FR-002**: Установка MUST NOT требовать предварительной установки графического тулкита в систему; базовые системные библиотеки (glib, OpenGL, fontconfig, xkbcommon, D-Bus) MUST быть перечислены в документации как требование к системе (FR-012).
- **FR-003**: После установки приложение MUST запускаться по короткому имени из любого каталога.
- **FR-004**: Приложение MUST работать на любом распространённом Linux-десктопе, включая GNOME, не требуя компонентов, специфичных для KDE.
- **FR-005**: Приложение MUST работать независимо от каталога с исходным кодом: удаление этого каталога не влияет на запуск.
- **FR-006**: Если mpv не найден, приложение MUST показать понятное сообщение с командами установки для распространённых дистрибутивов, MUST NOT завершаться и MUST NOT терять сделанный выбор файлов.
- **FR-007**: После появления mpv в системе запуск MUST работать без перезапуска приложения.
- **FR-008**: Пользователь MUST иметь возможность указать путь к mpv в файле настроек; пустое значение означает поиск в PATH.
- **FR-009**: При первом запуске MUST открываться папка загрузок пользователя, в том числе при локализованном имени этой папки.
- **FR-010**: Приложение MUST попадать в меню приложений по отдельной документированной команде — с названием и значком, без запуска из терминала.
- **FR-011**: Повторная установка MUST заменять предыдущую версию на новую без ручного удаления.
- **FR-012**: Документация MUST называть требования к системе: необходимость mpv, минимальные версии дистрибутивов и наличие подключения к сети при установке.
- **FR-013**: Документация MUST приводить команды установки mpv для распространённых дистрибутивов и для Flatpak.
- **FR-014**: Существующее поведение приложения (выбор файлов, автоподбор совпадения, «Следующая серия», ключи mpv, хранение настроек) MUST остаться без изменений.
- **FR-015**: Имена файлов MUST передаваться процессу mpv списком аргументов, без сборки командной строки оболочки.

### Key Entities

- **Установочный пакет**: набор для установки приложения для текущего пользователя; содержит исполняемый модуль приложения и метаданные версии.
- **Запись в меню приложений**: пользовательская запись запуска с названием, значком и командой вызова приложения.
- **Значок приложения**: изображение, используемое в меню и в списке задач.
- **Метаданные приложения**: название, описание, версия и ссылка на проект, показываемые системе и пользователю.
- **Путь к mpv**: пользовательская настройка (пустая или путь к исполняемому файлу).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Новая установка на системе без установленных графических библиотек занимает не больше 3 минут и требует не больше двух команд от пользователя (установка и запуск), без прав root.
- **SC-002**: 100 % запусков после установки проходят из произвольного каталога — без ошибок о ненайденных модулях.
- **SC-003**: При отсутствии mpv приложение не завершается ни в одном из проверяемых сценариев (0 падений) и в 100 % случаев показывает команду установки.
- **SC-004**: Проверка проводится минимум в 4 окружениях: KDE, GNOME-подобное окружение, графическая сессия X11 и «чистый» контейнер без графических библиотек; регрессий в поведении панелей нет ни в одном.
- **SC-005**: Инструкция содержит команды установки mpv минимум для 4 каналов (Debian/Ubuntu, Fedora, Arch, Flatpak).
- **SC-006**: После установки mpv запуск видео подтверждается без перезапуска приложения — 1 успешная проверка вручную.
- **SC-007**: Повторная установка новой версии выполняется одной командой и не требует ручного удаления старой.

## Assumptions

- Целевая платформа этого этапа — Linux. Windows и macOS вне объёма.
- mpv остаётся внешней зависимостью: пользователь ставит его сам из репозитория дистрибутива или через Flatpak. Приложение его не поставляет.
- Канал распространения — публичный каталог Python-пакетов плюс установка напрямую из репозитория проекта; имя пакета `media-picker` на момент планирования свободно.
- Графическая библиотека поставляется вместе с приложением, поэтому отдельная установка Qt не нужна — это и есть причина, по которой GNOME без Qt не является препятствием. Немного базовых системных библиотек (glib, OpenGL, fontconfig, xkbcommon, D-Bus) приложение всё же требует: на любом настольном Linux они уже есть, а в минимальном окружении их нужно доставить — это проверено в контейнере и записано в документации.
- Минимальные версии систем определяются версией системной библиотеки, которую требует поставляемая графическая библиотека: на момент планирования это Ubuntu 22.04+, Debian 12+, Fedora 35+. Более старые системы вне объёма этого этапа.
- Установка требует однократного подключения к сети.
- Интерфейс приложения не меняется: добавляются только предупреждение об отсутствии mpv, настройка пути к mpv и запись в меню приложений.
- «Один файл без установки» (образ приложения) и Flatpak-сборка — отдельный этап, вне объёма этой спеки.
- Локальная проверка на GNOME невозможна: рабочая машина на KDE, поэтому GNOME-подобное окружение проверяется переменными окружения и настройками платформы, а не отдельной установкой.
